- `.gitignore` now covers `logs/`, `data/chroma/`, coverage output and generated test results; checked by T-107 (S-07).- Catalogue generator `backend.catalogue` (`mock-data/build.py`, `make data`): 1,025 variants and 2,086 SKUs from the 342-row taxonomy with seed 20261017 (committed in `mock-data/generated/`), plus a git-ignored 5,125-variant scale set. Tags are derived from the lexicon; brands are invented `MockMart` names; prices, nutrition and stock are mock values (block 1.2, US-36).
- Validators V1 to V14 (`mock-data/validate.py`): run on both sets. V9 (needs the eligibility engine, block 1.3) and V12 (no retrieval query set yet) report NOT RUN; V7 checks stock counts, and its scenario-reference part waits for `stock_scenarios.json`.

- Eligibility engine `backend.engine.eligibility` (US-28; FR-60, 90, 91, 116): diet, faith, specialised diet, declared allergen, stock and add-on price cap masks in code. Every check re-derives tags from the ingredient list and keeps the stricter value, so a mis-tagged variant cannot pass on its tags (T-019). A dish is eligible when every essential ingredient has an eligible variant; optional lines without one are dropped. The add-on price cap uses the basket cost of the dish, excluding ingredients already in the cart (C18).
- Catalogue store `backend.catalogue.store`: products, SKUs and stock, with tiered ingredient resolution (plain product first, so `milk` never resolves to kulfi; aliases such as `jowar` narrow the group term `millet`) and scripted stock overrides.
- V9 now runs on the eligibility engine: every persona has at least 3 eligible mains, 1 companion and 1 SKU.
- Scoring `backend.engine.scoring` (US-17, US-18; FR-61, 66, 111; Appendix A): eligibility first, then `S_final = Σ ŵ_k s_k` over the survivors, with rank-based `s_p`, min-max for the others (equal inputs give 0.5), `ŵ = w / Σw` (all zero restores defaults), ties by `s_p` then ID, and a breakdown whose contributions sum to the score. Context `backend.engine.context` (FR-67) builds day type, part of day, season, festive window and weather from the clock or `CONTEXT_NOW` / `CONTEXT_WEATHER`; trend rows scale by their slider group (C23). Dish features `backend.engine.features` derive history buckets, premium level and the capped gender cohort boost (C24, C26).
- Variant choice `backend.engine.variants` (US-38; FR-113; ADR-008): `S_v = (1 − β) Σ ŵ_k s_k + β v`, with `β = 0.30 × (1 − gourmet_affinity)` and `v` from price per unit, a named attribute ("skimmed") restricting the eligible set, ties to the lowest price, and a reason plus alternatives for the cart line. The organic and gourmet sliders each change the milk chosen (T-035).
- `trends.csv` gains a `group` column and row T21 (summer cooling).
- Hybrid retrieval `backend.retrieval` (US-37, US-40, US-06; FR-110 to 113, 115, 117; ADR-004, 005): BM25 (`rank-bm25`) over dishes and ingredient terms with synonym phrases, embedded Chroma (`chromadb`, telemetry off) over `zest_dishes` and `zest_variants`, and reciprocal rank fusion (k = 60) into a 15-dish pool. Retrieval returns IDs and ranks only; `engine.recommend` then applies the guardrails, traces each removal as `guardrail_filtered`, ranks with the levers and returns an inspector payload. Vector store absent or failing: lexical plus synonyms, `fallback_used` traced; `RETRIEVAL_MODE=lexical` is the ADR-004 rollback. Ingredient names resolve to lexicon terms; a name matching several terms whose fused scores fall within `AMBIGUITY_MARGIN` asks a clarifying question (C27). `scripts/index.py` (`make index`) rebuilds the index only when the catalogue hash, embedder or Chroma version changes; the default ONNX all-MiniLM-L6-v2 embedder is downloaded once into the git-ignored `data/models/`. Unit tests use a deterministic hash embedder; `make test-embedder` runs the real one.
- Add-on suggestions (US-19; ADR-004 v2; FR-117 to 119): curated companions from `pairings.csv` by strength, plus vector neighbours of the cart dish's stored embedding restricted to `ADDON_COURSES` (course rule on the vector list only), merged by weighted RRF (curated 2, vector 1; ties by curated strength, then ID) into a pool of `ADDON_POOL`. Eligibility, including the add-on price cap (C18), runs after fusion, and removals are traced. With the vector store down, the curated list alone is used and `fallback_used` is traced. Suggestions never add anything to a cart (FR-64).
- Retrieval evaluation set `eval/datasets/retrieval_v1.jsonl` (61 queries: 15 mood, 20 ingredient, 16 regional, 10 variant; dev/test split), pre-registered in `MANIFEST.json` before any E5 run. V12 now runs (expected IDs may be dish IDs, variant IDs or `term:` lexicon terms); all of V1 to V14 pass.
- Input guard, rules arm `backend.guard.screen()` (ADR-006; FR-10, 12; Agent Design §7.1): injection, hazard and off-topic rules in code before any model call; violent-sounding cooking verbs pass; instructions inside fetched transcripts return MSG-INJECT-DATA. The Llama Guard arm is measured in E4 before adoption.
- Ollama JSON client `backend.llm` (Agent Design §5, §8; NFR-10, 11): temperature 0, JSON format, per-call timeout, one retry that names the error, Pydantic schemas with business validators (at most 40 ingredients, plausible names), `llm_call` traced without prompt text. Prompt file `recipe_extract_v1` with spotlighting of untrusted text.
- Variant lookup `Retriever.variants()` (FR-110): BM25 over variant names and ingredient lists plus `zest_variants` neighbours, fused into a pool of `VARIANT_POOL`; "skimmed milk" ranks the skimmed variant first.
- Evaluation harness `backend.evaluation` (Evaluation Plan §2, §6): Wilson 95% intervals, k/n proportions, recall@k, MRR, F1, result files with dataset hash and environment, thresholds read with `yaml.safe_load`. Day-1 scripts `scripts/benchmark/{retrieval,guard,text_models}.py` and `make eval-decisions` (E5, E4, E1); missing models are reported NOT RUN and never pulled. Smoke-checked on 3 dev rows only; **no evaluation has been run.**

### Changed
- Variant ingredient lists carry the product form as the first qualifier when the base product name differs from its lexicon term (`milk (milk powder, skimmed)`), so different products never share an ingredient list (Data Model §1.4). Two taxonomy rows that were still duplicates got a qualifier (`=boneless` on B317 tikka, `=filter mix` on B328 chicory coffee).
- Lexicon: `sarson` is now an alias of `mustard greens` only (it was also on `mustard seeds`; V10 caught the collision); added `non-food item` for household products.
- `dishes.csv` gains `aliases`, `flavour` and `description` columns, back-filled for D01 to D35 (C20); ingredient lines accept a fourth field `opt` for non-essential garnish lines. `check_seed.py` reads the new format.
