Scope: field-level schema for the structured catalogue, recipe base, engine inputs, session state, the retrieval documents embedded in Chroma, trace events and test fixtures. The Pydantic sketches are the contract the generator, validators, API and tests share. Field values in the mock data are illustrative and are not nutritional or medical data.

## 1. Principles
1. **Two stores, one truth.** Structured data (JSON files loaded into memory, optionally SQLite) is the only source of names, prices, packs, stock, tags and eligibility. Chroma holds embeddings of descriptive text only and returns IDs and similarity (FR-112, G9).
2. **Volatile or exact facts are never embedded:** price, stock, pack size and eligibility tags stay out of embedding text, so they cannot go stale or be matched fuzzily.
3. **Tags are derived, not typed.** Diet, allergen, halal and gluten flags on a variant are computed from its ingredient list through an ingredient lexicon, so the validators can prove them (risk R22).
4. **A variant is the unit of uniqueness.** A unique variant has a distinct ingredient list (owner decision, OQ-12). A SKU is a variant in one pack size. The shipped catalogue has at least 1,000 variants and therefore at least 1,000 SKUs.
5. **Session state is in memory** and resets on refresh (NFR-04).
6. **Seeded and reproducible:** every generated file is a pure function of the taxonomy, lexicon and seed (NFR-08).

### 5.4 Pairing
`dish_a` (the cart or main dish ID), `dish_b` (the companion dish ID), `strength` (0.3 to 0.9 in the seed; 0 to 1 allowed), `note`, as in `mock-data/pairings.csv`. The earlier field names (`main_dish_id`, `companion_type`, `companion_id`) are retired: add-on companions are always dishes, so `companion_type` is dropped; a base-product companion is not an add-on (it is a missing ingredient, on the existing path). For add-ons these rows are the *curated list*, one of two inputs to the add-on `s_p` (the other is the vector neighbours of the cart dish, section 7.4). Add-on companions (`dish_b`) are dishes of a companion course. Target size grows with the dish pool (about 60 rows in the first seed, more with 100 companion-course dishes); a dish without a row is served by the vector list alone.

## 6. Engine inputs

### 6.1 TrendRow
`group` (`indulgence` or `cooling`), `match` (category or dish tag), `day_type`, `weather`, `multiplier` (0.5 to 2.0). Effective multiplier for a candidate: `m_eff = 1 + L × (m − 1)`, where `L` is the matching trend slider. `s_t` is `m_eff` normalised over the pool.

### 6.2 Context (built per request)
`now` (datetime; overridable in config), `day_type`, `weather` (mock label from config), `festive` (bool). Never read from the LLM (FR-67).

### 6.3 Persona
`id`, `name`, `blurb`, `levers` (partial LeverSet; omitted fields use defaults), `test_prompts`. Already implemented in `mock-data/personas.json`.

## 7. Retrieval documents (what is embedded)

### 7.1 Collections
| Collection | One document per | Count | ID |
|---|---|---|---|
| `zest_dishes` | Dish | 35 now; at least 127 target (100 companion-course) | `dish:{dish_id}` |
| `zest_variants` | **Variant** (not SKU), because pack sizes would duplicate results | at least 1,000 | `var:{variant_id}` |

Distance: cosine. Embedding model and provider come from config (`EMBEDDING_PROVIDER`, `EMBEDDING_MODEL`); the default is Chroma's local ONNX embedder (all-MiniLM-L6-v2, per the Chroma documentation). Collection metadata records model name, library version and a hash of the catalogue; a mismatch triggers a rebuild.

### 7.2 Embedding text templates
**Dish:** `"{name}. {course} from {cuisine} cuisine. Mood and occasion: {mood_tags}. Taste: {flavour}. Main ingredients: {top 6 essential ingredients}. Also called: {aliases}. {description}"`

**Variant:** `"{name}. Category: {category}. {attribute phrase}. Ingredients: {ingredient_list}. Also called: {matching synonyms and default_names}."`
The attribute phrase turns attributes into words the user might say ("skimmed, low fat" or "whole wheat, high protein, organic").

**Excluded from all embedding text:** price, stock, pack size, brand, diet flags and allergens (eligibility is checked in code).

### 7.3 Metadata stored with each document
`kind`, `dish_id` or `variant_id`, `category`, `course`. Used for debugging and inspector display only. **Never used for guardrail filtering** (G9).

### 7.4 Query pipeline and fusion
| Step | Dish or mood query | Ingredient query |
|---|---|---|
| 1. Normalise | lowercase, strip fillers, expand synonyms | same |
| 2. Attribute parse | none | detect attribute words ("skimmed", "brown", "organic") against the attribute vocabulary; these become required attributes (FR-113) |
| 3. Lexical | top 20 by token overlap with names, aliases and synonyms | same, over variants |
| 4. Vector | top 20 from `zest_dishes` | top 20 from `zest_variants` |
| 5. Fuse | reciprocal rank fusion: `score = Σ 1 / (60 + rank_i)` | same |
| 6. Pool | top 25 dishes | top 10 variants |
| 7. Guardrails (code) | `M_elig` on each pool member | same |
| 8. Levers | rank survivors with `S_final` | `S_v` (FR-113) |

The constant 60, the pool sizes and the ambiguity margin 0.15 are config values tuned by the benchmark.

**Add-on query (ADR-004 v2).** Input: a dish in the cart. No new embedding is computed.

| Step | Add-on query |
|---|---|
| 1. Curated list | companions of the cart dish in `pairings.csv`, ordered by `strength` |
| 2. Vector list | top 20 neighbours of the cart dish's stored embedding in `zest_dishes`; exclude the dish itself and dishes already in the cart |
| 3. Course rule | keep only vector candidates whose `course` is in `ADDON_COURSES` (side, beverage, dessert); not applied to the curated list |
| 4. Fuse | weighted reciprocal rank fusion: `score = Σ w_i / (60 + rank_i)`, curated weight 2, vector weight 1 (`ADDON_WEIGHTS`) |
| 5. Pool | top `ADDON_POOL` candidates (config); the fused rank feeds the add-on `s_p` by rank-based normalisation |
| 6. Guardrails (code) | `M_elig` including the add-on price cap, on each pool member (G9) |
| 7. Levers | rank survivors with `S_final`; ties by curated strength, then ID |

If the vector store is unavailable, steps 2 to 4 are skipped and the curated list alone is used (`fallback_used`).

### 8.4 Cart, CartDish, CartLine
| Entity | Fields |
|---|---|
| `Cart` | `dishes: list[CartDish]`, derived `subtotal_inr`, `item_count` |
| `CartDish` | `cart_dish_id`, `dish_id` (or free-text name), `source` (Source), `servings`, `lines`, `added_by_suggestion_id` (for swap and Undo, FR-41) |
| `CartLine` | `line_id`, `cart_dish_id`, `ingredient_name`, `need_qty`, `need_unit`, `estimated` (bool), `variant_id`, `packs: list[PackItem(sku_id, count)]`, `priced` (bool), `shared_from_line_id`, `reason` (why this variant), `alternative_variant_ids` |

Pack allocation rule (FR-71, 73; v0.3, C33): for each variant, add up the need of every line that uses it, in cart order. Choose the pack set that covers the combined need with the least total quantity, then the fewest packs, then the lowest price, from in-stock SKUs within their stock counts (with the stock filter off and nothing in stock, the smallest pack is used and the line is marked out of stock). Lay the packs end to end and the line needs end to end: a pack belongs to the line whose need covers the pack's starting point, and that line is priced with it. A line that owns no pack is unpriced and dimmed, and `shared_from_line_id` points to the line that owns the pack covering the start of its need. Removing a line re-runs allocation, which transfers ownership. Examples: butter 100 g + 100 g → one 200 g pack, owned by the first line; paneer 200 g + 200 g → two 200 g packs, one per line. A need in a unit the packs do not use takes one smallest pack and the line is `estimated`.

Line quantity (FR-74; v0.3, C35): `quantity` (1 to 9, default 1) multiplies the packs the line owns, after allocation. A shared, unpriced line has no packs and takes no quantity. No pack count may exceed 9.

Quoted prices (FR-83; v0.3, C34): `Cart.quotes` keeps, per SKU, the price shown when the SKU first entered the cart. Buy Now compares it with the catalogue; it is never sent to the client.

## 9. Eligibility and tag rules (simplified, not medical advice; OQ-4)
Derived flags come from the ingredient lexicon. A candidate is eligible only if it passes **every** active rule (masks intersect, FR-09).

| Lever option | Rule on a variant | Rule on a dish |
|---|---|---|
| Pure Veg (Strict) | `diet_class` in {vegan, vegetarian}; no egg | All essential ingredients have an eligible variant |
| Jain (No Root Veggies / Pure Veg) and faith Jain (Strict Root-Free) | `jain_ok` = no meat, fish, egg, `root_veg`, `onion_garlic`, honey allowed | As above, or a dish variant (`variant_of`) exists |
| Non-Veg / Flexitarian | no rule | |
| Hindu (Shravan Month / Fasting Active) | `satvik_ok` = vegetarian, no `onion_garlic`, no `non_satvik` | As above |
| Muslim (Strict Halal Only) | `halal_status` in {halal, not_applicable}; no `alcohol`; no pork | As above |
| Hindu (Regular), None / Secular | no rule | |
| Keto Diet | `nutrition.carbs_g` ≤ 10 per 100 g (staples above this are filtered); dairy-fat and low-carb variants get a boost in `s_g` | Dish eligible if its non-optional main components pass |
| Intermittent Fasting / Low-GI | `gi_label` in {low, not_applicable} | |
| Vegan | `vegan` = true | |
| Gluten-Free | `gluten_free` = true | |
| High-Protein Fitness | No mask; variants with `protein_g` ≥ 10 per 100 g get a boost in `s_g` and in `kebabs` history | |
| Standard / Balanced | no rule | |
| Stock filter on | `stock_count` > 0 and `dark_store_ok` for at least one SKU | At least one in-stock SKU for every essential ingredient |
| Add-on price cap | Basket cost of the add-on dish ≤ cap (add-ons only): sum of the cheapest in-stock SKU for each non-optional ingredient at the dish's serving size, excluding ingredients already in the cart (C18, owner decision 2026-10-17) | |
| Declared allergen (chat, Could) | `allergens` does not contain the declared allergen | |

Gender never filters; it adds the capped cohort boost to `s_g` (at most 10% of that component, FR-07).

```python
from enum import Enum
from typing import Literal, Optional
from pydantic import BaseModel, Field


class Unit(str, Enum):
    g = "g"; kg = "kg"; ml = "ml"; l = "l"; piece = "piece"; bunch = "bunch"


class Pack(BaseModel):
    qty: float = Field(gt=0)
    unit: Unit


class Nutrition(BaseModel):
    carbs_g: float = Field(ge=0)
    sugar_g: float = Field(ge=0)
    protein_g: float = Field(ge=0)
    fat_g: float = Field(ge=0)


class Variant(BaseModel):
    variant_id: str
    base_id: str
    name: str
    category: str
    history_bucket: Optional[Literal["bakery", "dairy", "desserts", "salads", "kebabs"]] = None
    attributes: dict[str, str]
    ingredient_list: list[str] = Field(min_length=1)
    brand: str
    price_per_unit_inr: float = Field(gt=0)
    gourmet_score: float = Field(ge=0, le=1)
    organic_score: float = Field(ge=0, le=1)
    diet_class: Literal["vegan", "vegetarian", "egg", "non_veg"]
    flags: list[str] = []
    allergens: list[str] = []
    halal_status: Literal["halal", "not_halal", "not_applicable"] = "not_applicable"
    gluten_free: bool
    vegan: bool
    jain_ok: bool
    satvik_ok: bool
    nutrition: Nutrition
    gi_label: Literal["low", "medium", "high", "not_applicable"]
    icon: str
    embedding_text: str


class Sku(BaseModel):
    sku_id: str
    variant_id: str
    pack: Pack
    price_inr: int = Field(gt=0)
    stock_count: int = Field(ge=0)
    dark_store_ok: bool = True


class RecipeIngredient(BaseModel):
    dish_id: str
    line_no: int
    ingredient_name: str
    qty: float = Field(gt=0)
    unit: Unit
    scale_class: Literal["staple", "vegetable", "spice", "salt", "oil", "garnish", "liquid"]
    essential: bool = True
    substitute_group: Optional[str] = None
    attribute_hint: Optional[dict[str, str]] = None


class Dish(BaseModel):
    dish_id: str
    name: str
    aliases: list[str] = []
    course: Literal["main", "soup", "side", "snack", "breakfast", "dessert", "beverage"]
    cuisine: str
    base_servings: int = 2
    mood_tags: list[str]
    flavour: list[str] = []
    description: str
    history_bucket: Optional[str] = None
    trend_group: Optional[Literal["indulgence", "cooling"]] = None
    diet_class: Literal["vegan", "vegetarian", "egg", "non_veg"]
    variant_of: Optional[str] = None
    edge_case: bool = False


class Weights(BaseModel):
    culinary_pairing: float = Field(0.30, ge=0, le=1)
    purchase_history: float = Field(0.35, ge=0, le=1)
    market_trend: float = Field(0.20, ge=0, le=1)
    persona_gourmet: float = Field(0.15, ge=0, le=1)


class LeverSet(BaseModel):
    weights: Weights = Weights()
    gender: str = "Unisex / Neutral"
    diet: str = "Non-Veg / Flexitarian"
    faith: str = "None / Secular"
    specialized_diets: list[str] = ["Standard / Balanced"]
    gourmet_affinity: float = Field(0.50, ge=0, le=1)
    artisanal_organic: float = Field(0.60, ge=0, le=1)
    history: dict[str, float] = {"bakery": 0.85, "dairy": 0.70, "desserts": 0.65,
                                 "salads": 0.60, "kebabs": 0.75}
    trends: dict[str, float] = {"weekend_indulgence": 0.80, "cooling_drinks": 0.65}
    price_cap_inr: int = Field(200, ge=80, le=400)
    stock_filter: bool = True


class RetrievalTrace(BaseModel):
    lexical_rank: Optional[int] = None
    vector_rank: Optional[int] = None
    vector_distance: Optional[float] = None
    curated_rank: Optional[int] = None  # add-ons only
    curated_strength: Optional[float] = None  # add-ons only
    fused_score: float = 0.0
    fused_rank: int = 0


class ScoreBreakdown(BaseModel):
    s_p: float; s_h: float; s_t: float; s_g: float
    weights_effective: dict[str, float]
    value_term: Optional[float] = None
    eligible: bool = True
    filtered_by: list[str] = []
    final: float = 0.0


class Candidate(BaseModel):
    candidate_id: str
    kind: Literal["dish", "variant", "addon", "substitute"]
    retrieval: RetrievalTrace
    breakdown: Optional[ScoreBreakdown] = None


class PackItem(BaseModel):
    sku_id: str
    count: int = Field(ge=1, le=9)


class CartLine(BaseModel):
    line_id: str
    cart_dish_id: str
    ingredient_name: str
    need_qty: float
    need_unit: Unit
    estimated: bool = False
    variant_id: str
    packs: list[PackItem] = []
    priced: bool = True
    shared_from_line_id: Optional[str] = None
    reason: str = ""
    alternative_variant_ids: list[str] = []
    quantity: int = Field(1, ge=1, le=9)  # v0.3, C35: multiplies the packs this line owns


class Cart(BaseModel):
    dishes: list[CartDish] = []
    quotes: dict[str, int] = {}  # v0.3, C34: sku_id -> price when first carted; internal only
```

## 16. Open items
1. The `β0 = 0.20` value term (E12; was 0.30), pool sizes, RRF constant and ambiguity margin are initial values to be tuned (Day-1 benchmark and the lever-sensitivity test).
2. Whether to use a library for the lexical scorer (for example BM25) needs owner approval under G3; a simple token-overlap scorer needs no dependency.
3. Nutrition values are illustrative, generated from base-product templates; they are not nutritional data.
4. The ingredient lexicon is the highest-leverage file for guardrail correctness. A starter set of 92 terms was written first and has since grown to 203 terms (2026-10-17) to cover the dishes and the taxonomy; it exists in `mock-data/ingredient_lexicon.csv` (owner chose the starter option, 2026-10-17); validator V4 will report every missing term when the generator runs, and the gaps are then filled. Its flags are simplified and need owner review (for example ginger as a root vegetable, mushroom as non-satvik).
5. BM25 library approved in principle (G3); the exact package and version are confirmed at install and pinned (ADR-004).
