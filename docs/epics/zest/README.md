# Epic: Zest AI Sous-Chef

One epic, one feature set. Mirrors the playbook structure (`core/` for product-wide documents, `epics/` for the work).

| Stage | Folder | Documents |
|---|---|---|
| Discovery | `discovery/` | Product Research, Personas, Assumptions and Risk Register |
| Requirements | `requirements/` | BRD, Product Spec (PRD), User Stories and Traceability Matrix |
| Design | `design/` | Conversation Design, Architecture and ADRs (`design/adr/`), API Spec (no webhooks apply), Agent Design, Data Model, Security and Privacy Note, Mock Data Plan |
| Build and verify | `verify/` | Test Plan, Evaluation Plan (datasets and results go in `eval/` at the repo root) |
| Release | `release/` | Demo Script, Known Limitations and Responsible-AI Note, Prototyping Feedback |

Build handover: `build-plan.md`, `day-0-walkthrough.md` in this folder. Approval status of every document: `docs/core/approval-register.md`.

Repo-root release files: `README.md`, `.env.example`, `CHANGELOG.md`.
Foundation documents live in `docs/core/`.
